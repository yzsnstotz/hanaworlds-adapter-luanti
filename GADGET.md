# HanaWorlds Luanti Adapter 0.2.8 component candidate

Status: `PARTIAL`. The provider and payload are a component candidate. This is not a release or Stage 1 product proof; only the user can mark `ACCEPTED`.

## Scoped writer (world-adapter/v5)

`hanaworldsWorldAdapterV5` exposes Prepare, Apply and QueryPrepared only to the authenticated Canvas service. The scope includes every checked position and every public Canvas registered object footprint. `hanaworldsCanvasFootprintRegistry.readFootprints(worldRef, objectRefs, request)` must return `{current:true,durable:true,worldRef,objects}` with the exact current registered projections; a request's footprint cannot authenticate itself. This host service is resolved again on every Prepare and Apply. `hanaworldsLuantiNativeFacts.readScopedState` returns per-cell digests from the paired game snapshot. Callers pass `positions` for the complete scope and `protectedPositions` for cells their effect may write; omitting `protectedPositions` keeps the prior all-cell protection check. Each digest is SHA-256 over `HanaWorlds|adapter-scoped-cell/v1\n` followed by canonical JSON of `{profile,record}`. The private complete records stay in the Adapter journal.

Prepare and Apply both compare the same registered footprints and every actual game cell against the bound digests. Apply repeats this comparison immediately before the durable APPLYING barrier. The Luanti endpoint then checks the full saved scope once more before its first effect, and rechecks the original native grant, live privilege and protection at each effect. An edit outside the union cannot stale the transaction. The journal stores the complete scoped before image and digest; the narrower effect image is used only for write and trusted restoration. Successful Apply returns VERIFIED only after complete scoped readback; a failed or uncertain write follows the durable recovery states. The legacy `ReceiptProjection` revision fields use the explicitly namespaced `scope-state:` digest of real paired-world cells, never an invented whole-world revision. The v5 backend can operate without the old v4 whole-world/object revision oracle; old v4 mutations remain unavailable in that configuration.

## Provider boundary (world-adapter/v4)

`hanaworldsWorldAdapterV4` exposes only the `world-adapter/v4` runtime provider. Raw wire decoding precedes host authorization; bound validation follows fresh authorization and replay checks. The request `actorRef` is the Canvas service principal: authority comes from the current grant named by `authorizationRef` and, where present, the request `authorizationBinding`; the request `actorRef` is never used to authorize. Every transport and inspection operation requires the trusted Canvas domain owner.

- **Prepare** rechecks, before the durable barrier, each effect cell with the chained engine `is_protected` for the acting principal (`PERMISSION_DENIED/authorize/SCOPE_DENIED`) and then every connected player's actual `get_properties().collisionbox` against every effect cell (`SAFETY_INVARIANT_FAILED/validate/SCOPE_DENIED`). It then saves the complete before image and `beforeStateReadbackDigest = D(readback, readbackView(before image))` durably together and returns `PreparedTransactionResult`.
- **QueryPreparedTransaction** returns the same saved digest after restart; it never recomputes it from the live world. A record without an intact saved digest fails closed.
- **InspectRegion** is read-only. The anchor, facing, candidate search, per-cell protection, body overlap, occupancy and support are evaluated inside the Luanti payload (`region.lua`). Only the chosen region cells, their three-valued facts, protected/body cells inside the region, a cardinal `entranceFacing`, and (for `MULTIPLE_ONLINE_PLAYERS` only) the online player names leave the payload. The host computes the complete Luanti `Frame`, `frameDigest`, coverage and facts digests itself. The `Catalogue` (walkable facts and `catalogueDigest`) is read through the same trusted host inspection context that `InspectWorld` uses (`hanaworldsLuantiInspectionContext.readCatalogue`); without it the result is `CAPABILITY_UNAVAILABLE`. The window size is checked against the host capacity service (`LIMIT_EXCEEDED`, never truncated). Names and facts are released only after a second current-authorization check.
- Placement settings are Canvas-owned; the Adapter uses exactly the values Canvas sends and echoes them. It never applies a default.

## In-world renderer (interaction-surface/v3)

`/hanaworlds` shows the current Session frame. An action offering `PICK_WORLD_POINT` shows a pick button: the player points at a node, the payload raycasts along the look direction within the wielded item's own engine pointing range, asks for confirmation, then privately records the picked node, the picker, the picker's facing at pick time and the world, and relays only `{kind: PICK_WORLD_POINT, pickRef}`. An action offering `SELECT_CHOICE` is shown as "choose in Shell"; an in-world `SELECT_CHOICE` invocation is answered locally with `RENDERER_CAPABILITY_UNAVAILABLE/validate/SCOPE_DENIED/NONE` and never relayed. Every relayed in-world invocation is first recorded (invocation, session, world, player name) in the Adapter engine-state file `hanaworlds_adapter_engine_state.json` in the world directory, written with Luanti `safe_file_write` (fdatasync + rename). That file is the only place raw pick facing/position is kept.

Fail-closed paths keep their cause: a Lua error in a courier command is logged on the server with its operation and file:line (coordinate tuples and fractional numbers redacted); catalogue, saved-digest and principal-check failures are logged on the host with the operation and transaction/inspection id. No pose, position or owner data is logged.

Workshop relay: the `hanaworldsWorkshop` facade (`invokeAction(request, principal)`, `verifyFrameDelivery({worldRef, engineActorName, frame, authorizationRef})`) is looked up when an in-world action or frame arrives, not when the Adapter starts, because the install order starts the Adapter before Workshop. A missing or withdrawn facade refuses with `RENDERER_CAPABILITY_UNAVAILABLE`, nothing is relayed and the cause is logged; a facade refusal (for example a revoked grant) is never turned into a receipt. Frame proofs must match the exact world, player, session and grant.

Durable journal location: the Adapter keeps its transaction journal under the native DSH home, read from the host seam `ctx.get('dshHomePath')`, at `<DSH_HOME>/data/hanaworlds-adapter-luanti/journal/<sha256(worldRef)>`. The home must exist and, when `DSH_HOME` is set to a non-blank value, equal it as DSH itself resolves it (a leading `~`, `~/` or `~\` expands to the user home before resolving). Every component must be a real directory whose canonical path stays inside the home, and missing levels are created only inside it. A `world-binding` marker ties the directory to its world. Records without a marker, or a corrupt or foreign marker, fail closed (`ADAPTER_STORAGE_UNAVAILABLE`, cause logged; no transaction backend for that world) and are never adopted or replaced by a fresh identity. The journal survives a current Adapter restart because it is outside the package.

Host services: `hanaworldsAuthority`, `hanaworldsOperatorAuthority` and `hanaworldsRemoteTunnelFactory` are looked up at each use, like the Workshop facade, so a provider registered after the Adapter is used and a withdrawn one denies (no cached grant). `AuthorizeBinding` reports `recoveryGuarantee: RECOVERABLE_VERIFIED` and the exact `state-profile/v2` profile only when a recoverable backend exists for the bound world; otherwise both stay `null`. `engineBounds` and `limits` stay unavailable until an attributed source exists. The current operator access is checked after the grant and before the replay cache and any effect (revocation precedes replay): for a local world the operator's `BIND_RUNNING_WORLD` proof, for a remote world the operator authority and tunnel factory. Because a local and a remote connection may share a `worldRef` while normal requests carry only `worldRef`, the check uses the connection whose transport serves that world; a different connection cannot bind the same `worldRef` onto it, and an unbound shared `worldRef` fails closed. Ownership is reserved before any asynchronous transport open, so concurrent binds of one `worldRef` from different connections cannot both succeed; concurrent binds from the same connection share one transport and backend; a binding counts as accepted only after its public response validates; a failed attempt releases its reservation and drops the backend and transport it created unless a binding was accepted or the journal holds unsettled records (a backend merely existing is not a recovery record). A world held only for recovery serves trusted recovery, not normal operations, and is released (reservation, backend and transport) once trusted recovery settles its last unsettled record with no binding or recovery call in flight. A world's reservation is released only after its transport has actually closed: a rejected close is logged and leaves the world held with its transport still managed; the next binding for that world (or shutdown, which reports failures) attempts the close again, and no second transport is opened meanwhile. A rejected close is reported only by the fixed code `TRANSPORT_CLOSE_FAILED` and the world's `worldRef`; the provider's exception text (which may carry a URL or credential) is never logged or returned. Likewise an engine-principal check failure is logged only as `ENGINE_PRINCIPAL_UNVERIFIED`, and a catalogue provider failure only as `CATALOGUE_READ_FAILED` or `CATALOGUE_INVALID`; tunnel and provider exception text is not logged. A withdrawal refuses binding replays and non-recovery operations on every call; the backend, journal and existing tunnel are kept as the recovery handle so trusted service recovery (`RestoreTransaction`, `AbortPrepared*`) can still complete prepared or pending transactions. The transaction backend's engine-binding and service-recovery checks resolve the named `hanaworldsAuthority` at each call (never the facade present when the backend was built) and fail closed when it is absent. The managed local lifecycle below consumes the delivered public native-engine Host service. Other Session, transaction, and remote providers remain separate composition inputs.

## Settings and invariants

The Adapter has no product settings. Its correctness invariants (never guess a player, no silent relocation, names only to an authorized principal, pose stays in the engine, per-cell protection, body recheck at Prepare, Adapter-computed frame) are listed read-only in the loopback `status` projection with the reason each cannot be switched off. The pick range is the engine's own item pointing range (item definition `range`, engine default 4), not a HanaWorlds limit.

## World automatic authorization (S1-AD-AUTO-01, 0.2.7)

On joining the world, a native administrator or singleplayer world owner receives the existing world authorization form with an "Automatic authorization" button. Clicking it opens the existing automatic status panel without a chat command. Closing the form does not change the mode; leaving and rejoining the world offers the entry again, including when automatic authorization is already enabled. The entry checks the exact current online PlayerRef and current native authority again. Opening the panel only reads the mode; enabling or disabling still requires its explicit action. The existing `/hanaworlds_auto` command also opens that status form. Every online player may read it. Only a native player with `server` privilege, or the authenticated `singleplayer` account while `core.is_singleplayer()` is true, receives enable/disable buttons. The receive-fields callback checks that the exact native player object is still online, checks current administrator authority again, and rejects unsolicited or stale mode submissions. There is no courier or Shell write operation for this setting.

The default remains individual authorization. Enabled mode and its enabling native principal are stored in this world's mod storage. The enabling account must continue to exist and hold native authority (the administrator need not stay online). Identity loss, native server-privilege loss, or joining as a newly created enabling account disables the mode. Restoring authority alone does not re-enable it. Each enable creates a new mode epoch, and every automatic proof is bound to that epoch, native player, world and `WORLD_BUILD_WITH_ENGINE_PROTECTION` scope. An offline player or one without both `interact` and `worldedit` gets no current proof. Privilege loss/account recreation invalidates that player's prior proof. A player regaining build permission while automatic mode remains enabled may receive a fresh proof without individual confirmation.

Disabling revokes automatic proofs and any prepared write bound to them. Existing explicitly confirmed personal grants remain separate; the existing `/hanaworlds_grant` flow resumes when mode is off. Enabling mode hides the individual confirmation/revoke controls while showing automatic authorization status. No build privilege, protection bypass or scope is granted by this switch: the existing v5 exact scope barrier and engine per-cell protection checks still run on every effect. A new automatic epoch never makes an old grant or prepared write current.

The private Host service `hanaworldsLuantiGrantEvidence.readCurrentLocalAuthorizationMode({worldRef})` reads `{worldRef,enabled,scope}` and, only when enabled, `{enabledBy,modeRef}` through the normal paired courier. It verifies unique world discovery, local operator authority, current payload handshake and native reply shape/world. It is a read-only fact, not an authorization issuer or Canvas decision. The existing list/current grant ports carry automatic proofs without changing admitted public wire contracts.

This implementation was self-tested with Node and Lua fixtures. Unified HanaWorlds App + native Luanti UI, product entry preparation, and leoventory same-byte verification are still for the independent validation worker. These fixture results do not establish product PASS or TO_TEST.


## Managed local lifecycle (S1-AD-LOCAL-PROVISIONING-01, 0.2.6)

`ctx.get('hanaworldsLuantiLocalWorlds')` is a trusted in-process service, registered through the normal DSH plugin loader. It has no HTTP product route. A Host consumer supplies product-managed canonical discovery roots and forwards ephemeral credentials from its native account selection; the Adapter stores neither passwords nor stopped authorization facts. The delivered Host `hanaworldsNativeEngineControl` performs existing-account native SRP, current `server` privilege checks, exact world/process binding and legitimate shutdown. No file ownership, JSON proof, click intent or later game grant substitutes for this authority.

- `setRoots({roots: absolutePaths})` validates canonical real directories; `discover()` returns all discovered worlds, including `payloadVersion: null`, `worldRef: null` before first installation. These are observations, not Session bindings or grants.
- `acquire({connectionRef,requesterRef,userPath,username,password,action})` accepts only `PROVISION_PAYLOAD` or `BIND_RUNNING_WORLD`. It generates its own unique native operation and returns an opaque Adapter `leaseRef` plus current world/action/native actor/process observations. `inspect({leaseRef,requesterRef,connectionRef})` requires fresh native verification. Observations cannot be submitted as proofs.
- `provision({leaseRef,requesterRef,connectionRef,transportPort?})` consumes a provisioning lease once. Only the Host's finite stopped-world callback may enter the Adapter-owned installer. Wrong world/requester, stale identity/process, withdrawn provider, lost privilege or saved/duplicate callbacks reject. First installation allocates a loopback courier port and creates new identity and pairing. An existing payload location cannot be provisioned again. The callback retains the Host world lock through installation.
- `pair({leaseRef,requesterRef,connectionRef})` requires a separate running-world lease, actual payload identity and exact current payload handshake. It shares the Adapter courier/reservation; it creates no Canvas Session, transaction backend or world-write grant. Configure the existing Adapter `serviceName` in the public profile patch.
- `readCurrentGrants({leaseRef,requesterRef,connectionRef})` requires that paired current lease, verifies native authority before and after the read, and returns actual current game proofs for that exact connection/world. SRP/server privilege alone produces no world-build grant. Offline players, native build privilege loss, revoked game proofs or lost operator authority fail closed.

Every managed local operation re-resolves the same public native Host provider; removal or replacement invalidates its leases and never falls back to another operator provider. Adapter disposal closes its own courier and requests finite native stop for remaining owned leases through that same public service. It does not terminate unrelated processes or close the whole Host. The automatic mode, grant and protection logic is retained; the 0.2.7 native form entry above is the only behavioral addition.

The delivered HTTP Host component and official Luanti 5.17 are component inputs. Native account initialization, game/profile setup and trusted consumer selection in the repeatable component self-test are explicit fixtures. Formal App selection/login, installer/public engine distribution, independent product UI and clean-machine gates remain separate work.

## Public Host lifecycle (S1-AD-HOST-LIFECYCLE-01, Adapter 0.2.8)

Normal Host disable disposes the Adapter's own status-prefix route and its resources. The exact returned route handle is consumed once before asynchronous cleanup; an old close cannot remove a replacement instance's route. Concurrent closes share the in-flight cleanup, and a rejected cleanup can be attempted again. Cordis owns all provided service effects and withdraws them on unload or failed activation; the Adapter does not delete another fiber's service. The public Host's duplicate-route and management-required protections are unchanged.

The candidate package is 0.2.8 while its payload version and every payload file remain 0.2.7. No game authority, automatic mode, scope, protection, courier or transaction logic changes. The isolated test uses the fixed INSTALL75b5 Host and bundled Node, with fresh seed/profile preparation labelled SOURCE/FIXTURE and public pluginManager/HTTP actions labelled REAL_RUNTIME only for this component. It does not prove formal product immediate enablement, native game UI, INSTALL/AUTO/SLICE completion or user acceptance.
