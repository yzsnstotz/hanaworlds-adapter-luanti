# HanaWorlds Luanti Adapter 0.2.0 component candidate

Status: `PARTIAL`. The provider and payload are a component candidate. This is not a release or Stage 1 product proof; only the user can mark `ACCEPTED`.

## Ownership and license

This repository owns `world-adapter/v4`, its Luanti payload, and the native in-world renderer for `interaction-surface/v3`. Canvas owns world selection, named objects, the placement settings, the region inspection record, history, affected-object policy and product success; it is the only caller of every transport and inspection operation. The owner source is MIT under `LICENSE`; see the file-level `LICENSE_AUDIT.md`. The payload calls a separately installed WorldEdit API, pinned for diagnostics to revision `62ffafe3bcb386600c431ef3840d91c3c8f85639`; WorldEdit remains AGPL-3.0 and is not bundled. `canonicalize@5.1.0` remains Apache-2.0. `NOTICE` retains both boundaries. The package is private as a registry publication guard.

## Contract input

`hanaworlds-contracts@0.3.0` (public git revision `e82735780bdfd4ea8e662781455040a6e5306121`) is bundled under `vendor/hanaworlds-contracts` as the byte-identical subset the Adapter uses (its runtime import closure, test fixtures, and package metadata and notices; the 172 MB of JSON schemas it never reads are not bundled) and imported through the package `imports` aliases `#contracts/v3`, `#contracts/v4` and their fixture paths, so the only dependency is `canonicalize@5.1.0` from the registry and default pnpm 11 (`blockExoticSubdeps`) installs the Adapter as a git-hosted plugin. `npm run verify:contracts` checks every bundled file against `vendor/hanaworlds-contracts.manifest.json` (all 923 entries of the admitted package, sha256 `47a2e5cc77590fb471ffedde715682564e169a0d88dbc5005b71d8d542b38f5c`) and that the runtime import closure is bundled; `npm run verify:contracts:source` re-derives that package from public source and requires the same digest and manifest. The provider advertises the package's `ContractHandshake` (world-adapter/v4, interaction-surface/v3, target-facts/v2 and /v3); a 0.2.1 peer fails that handshake. No `file:` dependency, local tarball or sibling path is used.

## Provider boundary (world-adapter/v4)

`hanaworldsWorldAdapterV4` exposes only the `world-adapter/v4` runtime provider. Raw wire decoding precedes host authorization; bound validation follows fresh authorization and replay checks. The request `actorRef` is the Canvas service principal: authority comes from the current grant named by `authorizationRef` and, where present, the request `authorizationBinding`; the request `actorRef` is never used to authorize. Every transport and inspection operation requires the trusted Canvas domain owner.

- **Prepare** rechecks, before the durable barrier, each effect cell with the chained engine `is_protected` for the acting principal (`PERMISSION_DENIED/authorize/SCOPE_DENIED`) and then every connected player's actual `get_properties().collisionbox` against every effect cell (`SAFETY_INVARIANT_FAILED/validate/SCOPE_DENIED`). It then saves the complete before image and `beforeStateReadbackDigest = D(readback, readbackView(before image))` durably together and returns `PreparedTransactionResult`.
- **QueryPreparedTransaction** returns the same saved digest after restart; it never recomputes it from the live world. A record without an intact saved digest fails closed.
- **InspectRegion** is read-only. The anchor, facing, candidate search, per-cell protection, body overlap, occupancy and support are evaluated inside the Luanti payload (`region.lua`). Only the chosen region cells, their three-valued facts, protected/body cells inside the region, a cardinal `entranceFacing`, and (for `MULTIPLE_ONLINE_PLAYERS` only) the online player names leave the payload. The host computes the complete Luanti `Frame`, `frameDigest`, coverage and facts digests itself. The `Catalogue` (walkable facts and `catalogueDigest`) is read through the same trusted host inspection context that `InspectWorld` uses (`hanaworldsLuantiInspectionContext.readCatalogue`); without it the result is `CAPABILITY_UNAVAILABLE`. The window size is checked against the host capacity service (`LIMIT_EXCEEDED`, never truncated). Names and facts are released only after a second current-authorization check.
- Placement settings are Canvas-owned; the Adapter uses exactly the values Canvas sends and echoes them. It never applies a default.

## In-world renderer (interaction-surface/v3)

`/hanaworlds` shows the current Session frame. An action offering `PICK_WORLD_POINT` shows a pick button: the player points at a node, the payload raycasts along the look direction within the wielded item's own engine pointing range, asks for confirmation, then privately records the picked node, the picker, the picker's facing at pick time and the world, and relays only `{kind: PICK_WORLD_POINT, pickRef}`. An action offering `SELECT_CHOICE` is shown as "choose in Shell"; an in-world `SELECT_CHOICE` invocation is answered locally with `RENDERER_CAPABILITY_UNAVAILABLE/validate/SCOPE_DENIED/NONE` and never relayed. Every relayed in-world invocation is first recorded (invocation, session, world, player name) in the Adapter engine-state file `hanaworlds_adapter_engine_state.json` in the world directory, written with Luanti `safe_file_write` (fdatasync + rename). That file is the only place raw pick facing/position is kept.

Fail-closed paths keep their cause: a Lua error in a courier command is logged on the server with its operation and file:line (coordinate tuples and fractional numbers redacted); catalogue, saved-digest and principal-check failures are logged on the host with the operation and transaction/inspection id. No pose, position or owner data is logged.

Workshop relay: the `hanaworldsWorkshop` facade (`invokeAction(request, principal)`, `verifyFrameDelivery({worldRef, engineActorName, frame, authorizationRef})`) is looked up when an in-world action or frame arrives, not when the Adapter starts, because the install order starts the Adapter before Workshop. A missing or withdrawn facade refuses with `RENDERER_CAPABILITY_UNAVAILABLE`, nothing is relayed and the cause is logged; a facade refusal (for example a revoked grant) is never turned into a receipt. Frame proofs must match the exact world, player, session and grant.

Durable journal location: the Adapter keeps its transaction journal under the native DSH home, read from the host seam `ctx.get('dshHomePath')`, at `<DSH_HOME>/data/hanaworlds-adapter-luanti/journal/<sha256(worldRef)>`. The home must exist and, when `DSH_HOME` is set to a non-blank value, equal it as DSH itself resolves it (a leading `~`, `~/` or `~\` expands to the user home before resolving). Every component must be a real directory whose canonical path stays inside the home, and missing levels are created only inside it. A `world-binding` marker ties the directory to its world. Records without a marker, or a corrupt or foreign marker, fail closed (`ADAPTER_STORAGE_UNAVAILABLE`, cause logged; no transaction backend for that world) and are never adopted or replaced by a fresh identity. The journal survives Adapter restart and package remove/reinstall because it is outside the package.

Host services: `hanaworldsAuthority`, `hanaworldsOperatorAuthority` and `hanaworldsRemoteTunnelFactory` are looked up at each use, like the Workshop facade, so a provider registered after the Adapter is used and a withdrawn one denies (no cached grant). `AuthorizeBinding` reports `recoveryGuarantee: RECOVERABLE_VERIFIED` and the exact `state-profile/v2` profile only when a recoverable backend exists for the bound world; otherwise both stay `null`. `engineBounds` and `limits` stay unavailable until an attributed source exists. The current operator access is checked after the grant and before the replay cache and any effect (revocation precedes replay): for a local world the operator's `BIND_RUNNING_WORLD` proof, for a remote world the operator authority and tunnel factory. Because a local and a remote connection may share a `worldRef` while normal requests carry only `worldRef`, the check uses the connection whose transport serves that world; a different connection cannot bind the same `worldRef` onto it, and an unbound shared `worldRef` fails closed. Ownership is reserved before any asynchronous transport open, so concurrent binds of one `worldRef` from different connections cannot both succeed; concurrent binds from the same connection share one transport and backend; a binding counts as accepted only after its public response validates; a failed attempt releases its reservation and drops the backend and transport it created unless a binding was accepted or the journal holds unsettled records (a backend merely existing is not a recovery record). A world held only for recovery serves trusted recovery, not normal operations, and is released (reservation, backend and transport) once trusted recovery settles its last unsettled record with no binding or recovery call in flight. A world's reservation is released only after its transport has actually closed: a rejected close is logged and leaves the world held with its transport still managed; the next binding for that world (or shutdown, which reports failures) attempts the close again, and no second transport is opened meanwhile. A rejected close is reported only by the fixed code `TRANSPORT_CLOSE_FAILED` and the world's `worldRef`; the provider's exception text (which may carry a URL or credential) is never logged or returned. Likewise an engine-principal check failure is logged only as `ENGINE_PRINCIPAL_UNVERIFIED`, and a catalogue provider failure only as `CATALOGUE_READ_FAILED` or `CATALOGUE_INVALID`; tunnel and provider exception text is not logged. A withdrawal refuses binding replays and non-recovery operations on every call; the backend, journal and existing tunnel are kept as the recovery handle so trusted service recovery (`RestoreTransaction`, `AbortPrepared*`) can still complete prepared or pending transactions. The transaction backend's engine-binding and service-recovery checks resolve the named `hanaworldsAuthority` at each call (never the facade present when the backend was built) and fail closed when it is absent. None of these host services has a producer in a clean DSH today.

## Settings and invariants

The Adapter has no product settings. Its correctness invariants (never guess a player, no silent relocation, names only to an authorized principal, pose stays in the engine, per-cell protection, body recheck at Prepare, Adapter-computed frame) are listed read-only in the loopback `status` projection with the reason each cannot be switched off. The pick range is the engine's own item pointing range (item definition `range`, engine default 4), not a HanaWorlds limit.

## Build and isolated lifecycle

Run `npm ci`, `npm run verify:contracts`, `npm test` (needs `lua` in PATH for the region conformance harness), `npm run test:lua` and `npm run build` with Node 24.13.1 from a clean public clone with an isolated HOME/cache. Install with the supported DSH plugin lifecycle in a fresh profile. Payload provisioning upgrades a verified 0.1.0 or 0.1.1 payload to 0.2.0 while keeping the world identity, transport pairing and a versioned backup; `rollbackLocal(worldPath, '0.1.1')` restores those exact backup bytes on a stopped world and keeps the 0.2.0 directory beside it. If no current payload exists but a backup or retained payload directory still carries an identity (for example after a crash between the two renames of an upgrade or rollback, or after an uninstall), provisioning fails closed with `RECOVERY_PENDING` naming those directories; the operator chooses `restoreLocal(worldPath, directory)` (verified bytes, same identity) or `provisionLocal(worldPath, port, { freshIdentity: true })` (new identity). A failed directory sync after a completed swap is reported as-is, never undone. The journal and the engine-state file are never deleted by upgrade, rollback or uninstall. `test/real-lifecycle.mjs` remains a `REAL_RUNTIME` diagnostic only; it does not produce `REAL_UI` or product proof.

The release path still requires independent specification review, quality review, public remote readback, product composition and user-visible manual validation.
