# Adapter Host lifecycle implementation plan

**Goal:** Public setBundleEnabled enables, disables and enables Adapter again in one fixed Host without leaving a route/service.
**Architecture:** Keep the exact webServer.register disposer in each Adapter instance. service.close synchronously consumes it before asynchronous resource cleanup. Share an in-flight/successful close promise; clear only a rejected close promise so current resources retain their existing retry semantics. Cordis owns the provided service effects and rolls them back on unload/start failure; no manual cross-instance service deletion.
**Tech stack:** Existing Adapter ESM, pinned official DSH Host/Cordis and Node from INSTALL75b5; fixture fresh seed profile under this card R only. No GUI, game, grants or formal install.

Approved design: current CARD explicitly requests this narrow own-origin lifecycle repair. Root-cause code confirms discarded route disposer; restarting Host or changing its duplicate/management guard would mask/expand the defect. A route-only event callback would leave explicit service.close and repeated old-close ownership unproved, so close owns the one-time handle. Self-review: no new framework, no contract/payload/authority behavior, no other-origin source imports in production. Execute inline via executing-plans, sole original writer, no subagents or renewed owner question.
